# Collection value and composition

Read when assessing a collection's usefulness, ownership, or intended combinations.
Do not require these decisions for an ordinary review of one skill.

## Added value

Name the decision or constraint that the skill contributes beyond base agent
capability and existing project instructions. Use a concrete request where it
matters, plus an adjacent request where it should stay inactive. Generic wording
may suggest uncertain value; brevity, overlap, and non-use in one run do not prove
uselessness. Distinguish an unsupported benefit claim from a proven task defect.

When recommendations are requested, connect each to evidence: keep a distinct
useful role; narrow a trigger that captures the wrong task; merge only when task
ownership and required branches coincide and standalone behavior survives; retire
only with demonstrated obsolescence or replacement covering the intended contract.
If that evidence is absent, give the uncertainty and a useful comparison to resolve
it. A recommendation does not authorize removal or migration.

## Composition

Select a realistic requested combination, such as a task workflow with platform
or presentation guidance. Read the applicable instructions and define one combined
contract: scope, tools, authorization, completion, and output. Follow current
user/project requirements; different preferences alone are not a conflict.

Check whether each role contributes within that contract. Look for incompatible
actions, duplicate inspection or deliverables, required resource loads unrelated to
the task, and style rules changing implementation or mutation authority. Overlap
can be deliberate protection of a standalone invariant; do not delete it by default.
The combination should produce the requested result without requiring sibling
skills to operate independently.

Cite the interacting rules and condition. Written review predicts an interaction;
only an observed combined run proves it happened. For behavioral or cost claims,
read [references/evaluation.md](references/evaluation.md) and compare equivalent
outcomes, preserving unknowns and accepted tradeoffs.
