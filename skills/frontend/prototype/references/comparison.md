# Comparing UI directions

Read when building a comparison preview or promoting a chosen variant.

Choose a reusable story/preview route when one exists. In a standalone context,
a self-contained artifact may suffice. Keep the selector outside the subject being
judged and keyboard operable, with a visible selected state. Switching should not
add delay or erase meaningful context unexpectedly.

Hold data and task states comparable: a spacious layout and a dense layout should
solve the same task with the same information. Test the real container width and
relevant adjacent content, not only a full-width canvas. When interaction is the
difference, include its loading, error, and completion behavior as applicable.

Use a compact comparison: direction, decision axis, user benefit, tradeoff, and
preview location. Recommend a choice when asked or delegated; keep assumptions
visible. A count of variants or a screenshot quota is not a quality criterion.

After an authorized choice, integrate through normal component boundaries. Check
that temporary fixtures, selector state, and preview-only imports stay outside the
production path. Remove only disposable artifacts owned by this run, retaining
shared previews the project maintains. The production result needs its own check;
a working harness does not prove routing or integration is correct.
