## Decision cases

Parent instruction review on 2026-10-06 in the current Codex session; model version
not recorded. Cases review the written rules, not independent optimization execution.

| Request or condition | Expected decision | Review result |
| --- | --- | --- |
| Repeated lookup dominates a representative request | Attribute contribution and choose a scoped correction | No optimization based on file size or fashion |
| Only measurement is requested | Return measured evidence and proposals | No source edit inferred from a benchmark |
| No reproducible baseline or target environment | Report missing evidence and a discriminating capture | No invented speedup |
| Heavy profiler favors one implementation | Use profiling for attribution and representative matched comparison | Instrumentation overhead remains explicit |
| Cold-start task has expensive setup | Include relevant startup cost | No warm-only result presented as cold-start improvement |
| Cache proposal changes freshness or mixes tenants | Preserve the required contract and ownership | No silent consistency or isolation relaxation |
| More workers improve throughput but worsen tail latency | Compare the actual objective and resource costs | No throughput-only success claim |
| Allocation count falls but peak memory is unchanged | Report each measured quantity separately | No inferred resident-memory improvement |
| Faster approximation changes output fidelity | Resolve the product tradeoff before dependent changes | No weakened correctness gate |
| Average looks better but stalls or noise dominate | Preserve samples and inspect relevant spread/tails | Qualified or inconclusive result |
| Baseline value is zero | Use an appropriate absolute comparison | No undefined percentage improvement |
| Correctness or integration check fails | Diagnose and preserve unrelated work; recover only owned changes | Failed validation is not success |
| Performance target already met | Stop without speculative rewrite | No optimization quota |
| Huge profile or unavailable service | Use selected summaries, interval queries, and coverage limits | No whole-trace dump or false complete analysis |
| Run budget exhausted | Report current evidence and next useful probe | No unlimited retry loop or unjustified broadening |
| Paid service or production load not authorized | Use scoped available evidence or disclose the gap | No live campaign inferred from a local optimization task |

## Input budget and limits

No universal profiler reducer is bundled. Native filters and selected intervals
depend on the project's tool. Default input is workload/metric and relevant cost
summaries; full traces and raw samples remain outside default input. A new reducer
needs explicit limits, omission recovery, and large-input/failure verification.
Mechanical ceiling and large-trace recovery are not measured for arbitrary tools.

Independent bottleneck selection, application-wide correctness, production benefit,
multi-platform measurements, and automatic routing remain unmeasured. References
are conditionally loaded original guidance with primary-source links.
