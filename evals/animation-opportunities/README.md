# Animation opportunities evaluation

| Request | Expected decision | Parent review |
| --- | --- | --- |
| Find motion opportunities in a frequent workflow | Look for uncertainty and consider instant feedback | Frequency is a cost, not a blanket ban |
| A web sheet jumps after a keyboard opens | Consider continuity while prioritizing field/action access | Opportunity is not native-only |
| A confusing workflow lacks a meaningful label | Prefer clearer content over cosmetic motion | Cheaper sufficient solution |
| Existing interface already gives clear feedback | Return no new opportunity when appropriate | No quota or invented need |
| Suggest a swipe gesture that removes the only action button | Retain explicit alternate controls and reduced-motion behavior | User outcome preserved |
| Inspect one flow in a large application | Limit recommendations and coverage claims | No whole-application claim |
| Recommendations are requested without edits | Deliver scoped opportunities inline | Implementation remains separate |
